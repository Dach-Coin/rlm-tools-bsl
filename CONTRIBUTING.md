# Как внести вклад

Спасибо за интерес к проекту! Ниже — краткое руководство для контрибьюторов.

## Поддерживаемые форматы исходников

Поддерживаются **только два** формата выгрузки исходников конфигурации:

- **CF** — штатная выгрузка Конфигуратора («Выгрузить конфигурацию в файлы»)
- **EDT** — проект 1C:EDT (`.mdo`)

Другие форматы, в том числе сторонние распаковщики бинарных `.cf`, не поддерживаются и не будут. Метаданные разбираются из XML/MDO, поэтому на выгрузке в формате без этих файлов - работает только код-слой: методы, граф вызовов, полнотекстовый поиск. Роли, подписки на события, реквизиты, функциональные опции и формы при этом остаются пустыми — это не баг наших алгоритмов индексирования, а граница применимости.

**Обычные (неуправляемые) формы не поддерживаются и поддерживаться не будут.** Платформа выгружает такую форму одним бинарным файлом `Ext/Form.bin`, внутри которого и структура формы, и её модуль — текстового представления нет вообще. Индексировать там нечего по построению: рядом не появляется ни `Form.xml`, ни `Module.bsl`. Управляемые формы выгружаются текстом (`Ext/Form.xml` + `Ext/Form/Module.bsl`) и поддерживаются полностью.

## Быстрый старт

```bash
git clone https://github.com/Dach-Coin/rlm-tools-bsl.git
cd rlm-tools-bsl
uv sync --dev
```

## Запуск тестов

```bash
uv run pytest tests/ -v
```

Тесты запускаются без реальных конфигураций 1С — используются фикстуры с минимальными файловыми структурами.

## Линтер и форматтер

В проекте используется [ruff](https://github.com/astral-sh/ruff). CI проверяет линтинг и форматирование на каждый push/PR.

Проверить локально перед коммитом:
```bash
uv run ruff check src/ tests/      # линтер
uv run ruff format --check src/ tests/  # проверка форматирования
```

Автоформат:
```bash
uv run ruff format src/ tests/
```

Конфигурация — в `pyproject.toml` (секция `[tool.ruff]`).

### Pre-commit хуки (опционально)

Для автоматической проверки перед коммитом:
```bash
uv run pre-commit install
```

## Code style

- Python 3.10+
- Аннотации типов — норма, а не исключение: большинство функций пакета аннотировано, значительная часть модулей живёт под `from __future__ import annotations`. Следуйте стилю того файла, который правите. Статическая проверка (mypy/pyright) в CI пока не включена
- `ensure_ascii=False` во всех `json.dumps` — кириллица должна быть читаемой
- Документация и комментарии к коммитам — на русском языке
- Не хардкодить версию — она берётся из `pyproject.toml`

## Структура проекта

```
src/rlm_tools_bsl/       # основной пакет
  server.py              # MCP-сервер (rlm_start, rlm_execute, rlm_end, rlm_help, rlm_index, rlm_projects)
  bsl_helpers.py         # BSL-хелперы песочницы (самый большой модуль пакета)
  bsl_index.py           # SQLite-индекс: сборка (IndexBuilder) и чтение (IndexReader)
  bsl_xml_parsers.py     # парсеры XML-метаданных 1С, оба формата (CF и EDT)
  bsl_knowledge.py       # стратегия анализа, бизнес-рецепты, BSL-паттерны
  bsl_strategy_data.py   # текстовые секции стратегии (leaf-модуль, только stdlib)
  format_detector.py     # определение формата исходников, разбор путей BSL-файлов
  extension_detector.py  # расширения 1С и перехваты методов (&Вместо/&Перед/&После/...)
  sandbox*.py            # песочница: процессная изоляция, воркер, backend, протокол
  helpers.py             # базовые файловые хелперы (read_file, grep, glob_files)
  cache.py               # дисковый кеш координат BSL-файлов
  projects.py            # реестр проектов
  llm_bridge.py          # интеграция с LLM-провайдерами
  cli.py                 # CLI (rlm-bsl-index)
  service*.py            # установка как служба (Windows / Linux)
  log_retention.py       # ротация server.log
tests/                   # unit + integration тесты
docs/                    # документация
```

Полная карта модулей с зависимостями и точками расширения — **[docs/MODULE_MAP.md](docs/MODULE_MAP.md)**. Правите модуль — обновите и её.

## Версионирование

Проект публикуется в [PyPI](https://pypi.org/project/rlm-tools-bsl/). Если ваш PR изменяет код (не только документацию), **обязательно сделайте bump версии** в `pyproject.toml` и `uv.lock`:

- Багфиксы: `x.x.x` → `x.x.x+1` (patch)
- Новые фичи: `x.x.x` → `x.x+1.0` (minor)

Не забудьте добавить запись в `CHANGELOG.md`.

## Как отправить изменения

1. Форкните репозиторий
2. Создайте ветку от `master` (`git checkout -b feature/my-feature`)
3. Внесите изменения и убедитесь, что тесты проходят
4. Если изменён код — сделайте version bump в `pyproject.toml`, обновите `uv.lock` (`uv lock`), и добавьте запись в `CHANGELOG.md`
5. Отправьте PR с описанием: что изменено и зачем
